## Specs

S2. «Generar una previsualización PNG con el mapa de colores **Inferno**, respetando la máscara del ROI y utilizando transparencia fuera de ella.» «Utilizar una escala de colores explícita y devolver sus límites en W/m² para que el frontend pueda representar correctamente la leyenda.» «Incluir los límites geográficos de la imagen en EPSG:4326 para que pueda superponerse correctamente sobre un mapa.»
S3. «Guardar metadatos de la simulación: fecha, hora, posición solar, DNI, intensidad, condiciones atmosféricas, procedencia NASADEM y parámetros utilizados.» «La única capa autorizada es la **irradiancia directa incidente**.»
S4. «POST `/api/solar/simulations`» «ROI como GeoJSON Polygon o MultiPolygon en EPSG:4326.» «Fecha y hora local.» «Zona horaria IANA.» «Intensidad de radiación entre 0 y 100 %.» «Temperatura opcional, 12 °C por defecto.» «Presión atmosférica opcional en hPa; si no se proporciona, calcularla mediante atmósfera estándar utilizando NASADEM.» «La API deberá ejecutar el pipeline de las fases A, B, C y D y devolver un identificador de simulación junto con sus metadatos y enlaces a los resultados.»
S5. «GET `/api/solar/simulations/{id}`» «GET `/api/solar/simulations/{id}/preview/incident`» «GET `/api/solar/simulations/{id}/export/incident`» «GET `/api/solar/simulations/{id}/sample?lon=...&lat=...`» «El endpoint `sample` debe leer el raster numérico, no interpretar colores del PNG.»
S6. «No dependas de un `roi_id` que todavía no esté implementado; acepta directamente GeoJSON para que el frontend pueda integrarse.» «Valida geometrías, coordenadas, fechas, parámetros y límites razonables de procesamiento.» «Maneja errores con respuestas JSON claras.» «Evita operaciones costosas o inseguras con ROI demasiado grandes.» «Mantén coherencia entre GeoTIFF, PNG, límites geográficos y metadatos.» «No expongas rutas internas del servidor.» «Evita que un usuario pueda acceder arbitrariamente a archivos del sistema mediante identificadores o parámetros.»
